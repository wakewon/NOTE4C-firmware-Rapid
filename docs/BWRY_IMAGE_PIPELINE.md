# Note4C 四色图片转换管线设计说明

面向 ZECTRIX Note4C（400×300，SSD2683，B/W/R/Y 四色）。
硬件能力不变，设备颜色编码不变，SSD2683 刷新逻辑不变 —— 本文只覆盖「原图 → B/W/R/Y framebuffer」。

工具实现在 [`tools/bwry/`](../tools/bwry/README.md)。

---

## 1. 出发点：现在的算法错在哪

现有实现（`docs/inkscreen_image_converter.js`，以及 `ap_transfer_server.cc` 里内嵌的同一份 JS）：

```
RGB → 理想 B/W/R/Y palette → 亮度加权 RGB 最近色 → Floyd-Steinberg（raster） → 2bpp
```

拆开看有四个独立的问题，它们各自造成的损失是可以分别衡量的：

**a. palette 是假的。** 假设墨水是纯 `#000000 / #FFFFFF / #FF0000 / #FFFF00`。
实际 BWRY 电子纸的黑是深灰（媒体相对 L\*≈42），红是相当暗的砖红，黄是发闷的芥末黄。
按纯色算最近色，等于用一张错误的地图找路。

**b. 距离度量在 RGB 里。** `0.299·ΔR² + 0.587·ΔG² + 0.114·ΔB²` 是亮度加权，不是感知均匀。
偏蓝的阴影和红墨水之间的「距离」被严重低估。

**c. 没有色域映射。** 饱和的蓝天、青色、紫色在四色墨水里根本不存在。
不做映射直接进误差扩散，这些无法表达的残差会被推给邻居、不断累积，
最后由某个像素以一颗红点或黄点的形式「还清」—— 这就是灰墙、天空、肤色暗部上彩噪的直接来源。

**d. raster 扫描。** 固定方向的误差传播产生规则的 worm 纹理。

外加一个更隐蔽的问题，见 §3。

## 2. 屏幕实际四色校准

### 媒体相对表示

profile 用**媒体相对** sRGB 存四种墨水：面板自己的纸白按通道归一到中性 255。

理由有两条：

1. 它把环境光色偏除掉了。手机拍照标定时，光源色温是最大的误差来源。
2. 它丢掉的只是用不上的信息 —— 纸白之上没有更白的参考色，面板无法「还原」纸张本身的色偏。

顺带一个好处：黄墨水相对纸白的色相，才是抖色时真正该用的量。
如果纸张本身偏黄，那么黑白混出来的灰也偏黄，黄墨水离中性其实比看上去更近。归一化会自动把这件事算对。

### 内置 profile

| profile | 用途 |
| --- | --- |
| `note4c-measured-v1` | **实测，当前默认。** 由 Sony A7M2 RAW 标定 |
| `note4c-ideal` | 纯 RGB 原色。现有算法的假设，留作 A/B 基线 |
| `note4c-estimate-v1` | 早期估计值，只留作对照 |

估计值已被实测替换。两者差距远超预期：

| 墨色 | 估计 | 实测 | ΔE76 |
| --- | --- | --- | --- |
| black | L\*42.4 | L\*27.9 | 14.8 |
| yellow | L\*72.8 C\*51.2 | L\*96.3 C\*93.7 | **50.3** |
| red | L\*37.8 C\*43.6 | L\*49.1 C\*55.9 | 16.8 |
| 对比度 | 7.8:1 | **18.4:1** | |

#### 黄色在红通道上比白态还亮

实测黄色墨的红通道是白态的 **1.55 倍**。这不是相机处理：用每个色块正上方的白边做
局部参照（即控制了光照）之后依然成立。面板的「白」只是一层反射率有限的白色粒子，
而黄色颜料在 500nm 以上反射极强；黄色的**亮度**仍只有白态的 0.91 倍，不违反物理。

因此 profile 除 8bit sRGB 外还存 `linear`（媒体相对线性反射率，**允许 > 1**），
色度计算一律走它。裁进 sRGB 立方体会让黄色偏出 ΔE76 24、a\* 从 +12 翻到 −11 ——
描述成一块面板做不出来的绿黄色，进而带偏所有暖色的选色与误差扩散。

#### 半色调非线性：Yule-Nielsen n = 1.57

细网点里的亮墨达不到大色块的反射率，所以混色比线性平均暗。用 25/50/75% 灰阶
拟合得 `n = 1.57`，并由未参与拟合的彩色混色块独立验证（线性模型误差最大 +31.9%，
n 修正后 +6.7%）。

**这意味着抖动后的中间调在真机上比线性模型预测更暗。** 修正已作为
`dot_gain_compensation` 独立开关接入 dither，但 shipping preset 暂不默认开启。
`09-sierra2-edge` 与 `09b-sierra2-edge-yn` 除此开关外逐项相同，用来做真机定档。
人眼模拟与指标始终按实测 `n` 渲染，保证两个候选都以同一个物理面板为评分基准。

### 标定流程

```bash
bwryctl chart --out chart.bin --push http://<设备IP>   # 12 色块 + 四角定位标记
# 拍照
bwryctl calibrate chart.jpg --out my_profile.json
```

色卡里除四个纯色块外，还有 25/50/75% 的有序半色调混合块。
提取时会拿实测混合色和「两种墨水在线性反射率里平均」的预测值对比：

- ΔE 小 → 线性混合成立，色域四面体（§4）是可靠的模型；
- ΔE 大 → 存在明显光学扩张（dot gain），profile 只能当近似用，后续可以考虑引入非线性混合模型。

没有相机也可以直接喂色度计读数：`bwryctl calibrate --swatches '#5f6165,#fffdf8,#c8b055,#94413a'`。

合成数据回环验证（把色卡用已知 palette 渲染出来，再走一遍提取）在 `selftest.py` 里，
最大 ΔE76 = 0.00。

## 3. 感知空间 —— 以及一个比它更要紧的问题

按计划，选色改成 Lab + ΔE76。这一步是对的，也确实解决了 §1b。

但实现过程中量出来一个更大的问题：**误差扩散的工作空间，比距离度量的选择影响更大。**

半色调在视觉上是按**反射率线性**平均的。设备黑 Y=0.128、白 Y=1.0：

- 目标 L\*=71.2（正好落在两者中间）
- 在 **Lab** 里扩散误差 → 得到 50/50 混合（L\* 平均值确实是 71.2 ✓）
- 但这块 50/50 实际反射 Y = 0.564，光学上读出来是 **L\*≈79.7**

也就是说，在感知空间里扩散误差，每一块平坦区域都会**系统性墨量不足**。整张图发灰发白。

所以：

- **选色** 用 Lab ΔE76 —— 这才是防止偏蓝阴影被判给红墨水的东西；
- **残差** 默认在线性光（XYZ）里累积和传递；启用 dot-gain 修正时，则在
  Yule-Nielsen 的可加空间累积和传递，使真机积分后的平均色调命中目标。

自检分别验证两个表面：`n=1` 时平坦色块在线性光里积分命中目标；实测 `n=1.57` 时，
未修正的 50% 中间调偏出 ΔE76 > 5，而修正后 ΔE76 < 0.3、黑点覆盖率回到 50%。

A/B 矩阵把这一步单独拆成了一级（`01-cal-lab-fs` → `02-linear-error`），
`error_space="lab"` 也保留了下来 —— 这个失败模式值得摆到面板上并排看一次。

## 4. 色域映射：四面体

四种墨水空间混合能得到的颜色集合，恰好是这四个点在 **XYZ 中的凸包** —— 一个四面体。
（凸包必须在 XYZ 里算，不是 Lab；理由同 §3，混合是反射率线性的。）

映射做法：

1. 先把 L\* 映射到面板可达区间 `[L_black, L_white]`（黑点补偿）；
2. 保持色相，沿「目标点 → 中性轴锚点」的方向做二分搜索找到四面体边界；
3. 带 knee 的软压缩（默认 0.80），不是硬裁剪 —— 硬裁剪会让接近边界的渐变压成一片死板的平顶。

锚点位置由 `gamut_l_adapt` 控制：

- `0` —— 等 L\* 压缩，比色上严格，但明亮的红色会被压成灰；
- `1` —— 锚点滑到该色相的 cusp 亮度，让明度让位给饱和度；
- 默认 `0.35`（`photo`）/ `0.55`（`illustration`）。

四色 palette 只有两个彩色顶点，所以 cusp 亮度用色相加权混合近似，误差在 2 个 L\* 单位内，且是平滑的 —— 对这里而言平滑比精确更重要。

**这一步必须在抖色之前。** 这是 §1c 的正解：无法表达的颜色在进入误差缓冲之前就已经被投影到可达集合里了，
误差扩散再也没有机会把它们变成彩噪。

实测（Cubes.jpg）：映射前只有 1.3% 的像素在色域内，平均 chroma 12.0 → 映射后 1.54。
这个塌缩看着吓人，但它是物理事实：紫、青、绿、蓝在 BWRY 上不存在，只能走中性。
橙/黄/红色相的 chroma 是保住的。

## 5. Chroma gate

低色度区域优先交给黑白：

- 后色域 chroma < `c_lo`（默认 3.5）→ 彻底压回黑白轴；
- `c_lo` .. `c_hi`（默认 13）→ smoothstep 过渡；
- 同时给红/黄在选色时加一个随 gate 关闭程度增长的 ΔE penalty（默认 26）。

**但只做这两件事是不够的**，这是实现里第二个量出来的坑：

没有一种墨水是绝对中性的 —— 实测黑通常略偏蓝。
于是一长串黑白半色调会慢慢攒下一个反方向（偏黄）的彩色残差，攒够了就由某个像素还清成一颗黄点。
gate 拦住了*选色*，却拦不住*残差累积*。

所以 gate 关闭的地方必须**同时停止传递彩色残差**（`gate_error_floor`，默认 0，即完全不传）。
只衰减偏离中性轴的分量，亮度残差原样保留。

效果（Cubes.jpg，中性区彩噪率）：

| | rate_in_neutral |
| --- | --- |
| `03-tone-gamut`（无 gate） | 0.30% |
| `04-chroma-gate`（gate + 残差衰减） | **0.01%** |

30 倍。

## 6. 色调映射

面板的 L\* 可用跨度只有约 42..100，不到 sRGB 的六成。全局对比度必须让步 ——
所以细节要靠**局部对比度**找回来。

顺序：autocontrast（百分位黑白点，带 preserve-white）→ 曝光 → S 曲线（可调 pivot）
→ 暗部提升 → 高光压缩 → 局部对比度（两级 unsharp：大半径 + 细节）→ 饱和度 → 映射到面板区间。

其中所有**逐点**操作烘成一张单调 LUT：

- 任何参数组合都不可能产生非单调曲线（不会出现色阶断裂）；
- 曲线本身可以写进 A/B 的 sidecar，光看元数据就能复现结果。

## 7. 抖色

误差扩散核：Floyd-Steinberg、Sierra-2、Sierra-3、Sierra-Lite、Stucki、Jarvis、Burkes、Atkinson，
全部支持 serpentine 扫描。

另外两条路线：

- **有序蓝噪声** —— 对每个像素，在 6 个墨水对里找出「最优线性混合」最接近目标的那一对，
  再把混合比例对 void-and-cluster 掩模取阈值。完全向量化，没有扫描顺序痕迹。
  代价是需要三种墨水的地方会有残差。
- **混合** —— Sierra-2 + 蓝噪声调制决策阈值。噪声只影响*选择*，残差仍按真值计算，所以平均色调不受影响。

蓝噪声掩模用 Ulichney void-and-cluster 现场生成（64×64，可平铺）。
能量场增量维护 —— 增删一个少数像素只是加减一个环形移位的高斯，
所以是几毫秒而不是几千次完整卷积。自检验证了阈值是均匀排列，且低频能量占比 0.0008。

## 8. 边缘与内容保护

误差扩散最难看的地方恰好是图像结构最丰富的地方：文字、头发、树枝、建筑轮廓周围，
像素的残差被抹过边界，边缘长出一圈错色的晕。

做法：对色调映射后的 L\* 求 Sobel 梯度，按**百分位**（不是绝对阈值）归一化 ——
这样柔和的人像和硬边的截图都会得到合理比例的「边缘」，而不是其中一个直接饱和。
高梯度处按 `edge_suppress` 衰减残差传递。

在有序蓝噪声路线上，等价操作是把混合比例往 0/1 拉（软 snap）。

内容分类（`edges.classify`）会给出平坦度、强边缘比例、亮度熵、平均 chroma，
`convert` 会顺手打印它建议的 preset，可以拿来核对 preset 选得对不对。

### Preset

| preset | 取向 |
| --- | --- |
| `photo` | 适度 S 曲线 + 较强局部对比度，gate 收紧，Sierra-2 serpentine + 边缘保护 |
| `illustration` | 保饱和度（1.45×），gate 放宽，Atkinson 让平涂干净、线条锐利，`l_adapt` 拉到 0.55 |
| `text` | 硬色调曲线，chroma 几乎全关，误差扩散削到 0.55、边缘抑制 0.85 |

## 9. A/B 流程

内置矩阵是一条**每级只改一个变量**的阶梯，这样真机对比能回答「这一步值不值」，
而不是只能得出「新的看着好一点」：

```
legacy → 01-cal-lab-fs → 02-linear-error → 03-tone-gamut → 04-chroma-gate
       → 05-fs-serpentine → 06-sierra2 / 07-stucki / 08-atkinson
       → 09-sierra2-edge / 09b-sierra2-edge-yn（只差 dot gain）
       → 10-bluenoise → 11-sierra2-bluenoise-hybrid
       → 12-illustration / 13-text
```

每个 (图片 × 配方) 产出 `.bin` + 逐像素预览 + 人眼模拟预览 + `.json`（完整参数 / palette / 指标）。
任何一个 `.bin` 都能追溯回产生它的确切配方。

**公平性上有两个必须注意的点：**

1. **基线必须是真的基线。** `legacy` 是当前线上算法的忠实复刻，
   自检里有一条与 `docs/inkscreen_image_converter.js` 的**逐字节一致性**校验（30000/30000 字节相同）。
2. **所有候选按同一个物理现实打分。** 预览和指标一律用「面板实测 profile」渲染，
   不管该配方自己是按哪个 palette 做的决策。
   否则 `legacy` 会被按纯 `#FF0000` 评分 —— 那是任何电子纸都做不出来的颜色，对比就没有意义了。

### 指标

只用来缩小范围，**最终以真机为准**。

| 指标 | 含义 |
| --- | --- |
| `dE self` | 半色调离它自己的目标多远，衡量抖色器；只在共用色调曲线的配方间可比 |
| `dE ref` | 离朴素比色渲染多远。刻意的色调选择会抬高它，是描述不是评分 |
| `confetti` | 源图中性区域拿到红/黄墨水的比例。**越低越好，永远** |
| `anisotropy` | 半色调纹理方向性。worm 抬高它，蓝噪声压向 0 |

ΔE 都在 HVS 滤波之后算 —— 半色调逐像素比对没有意义，两边先过一个近似人眼空间响应的高斯。

## 10. 现状与下一步

**已完成并验证：** 实测 palette 框架 + 标定流程、Lab 选色、线性光误差扩散、
Yule-Nielsen 物理积分模型与可切换补偿、
四面体色域压缩、chroma gate（含残差衰减）、色调/局部对比度、5 类扩散核 + serpentine、
蓝噪声与混合路线、边缘保护、三个 preset、A/B 矩阵与对比页、自检。

**实测标定已完成**（`note4c-measured-v1`，A7M2 RAW），并已成为默认 profile。
标定过程中修掉的 4 个真实 bug 见 §11。

**下一步，按顺序：**

1. **真机 A/B 定档。** 把矩阵推到设备逐张看，选出照片路线的赢家。
   客观指标只负责把 15 个候选缩到 3～4 个。现在候选是基于实测 profile 生成的，
   预览与真机应当第一次真正对得上。
2. **给 Yule-Nielsen 修正定档。** 对比 `09-sierra2-edge` 与
   `09b-sierra2-edge-yn`；它会整体提亮中间调，必须真机决定是否进入默认 preset。
3. **移植到设备侧。** 真机定档之后，再把胜出配方移植到
   `ap_transfer_server.cc` 内嵌的网页和 `docs/inkscreen_image_converter.js`。
   现在移植是浪费 —— 参数还没定，而且两份 JS 一旦分叉就会长期不一致。
   在那之前，NAS / 脚本路线可以直接用本工具产出 `.bin` 再走 `/upload`。
4. **可选：** ΔE94 / CIEDE2000（当前误差扩散内层固定 ΔE76）、按内容自动选 preset。
5. **可选：重拍一张更亮的标定照。** 当前这张把面板压在传感器动态范围的下 1/8，
   黄色的蓝通道只比黑电平高约 14 ADU，8% 的采样点被钳到 0，
   使黄色存在约 ΔE 3 的不确定度。其余数据不受影响。

## 11. 标定过程中修掉的 bug

这 4 个都会**静默**产出一个看起来合理、实际错误的 profile，因此都补了回归测试：

| bug | 后果 |
| --- | --- |
| `find_marks` 把定位块和面板边框暗缝连成一个连通域 | 该角点偏移 280px，单应矩阵整体扭曲，把黑色块当成「白边」采样。回归测试里旧实现误差 196.5px，新实现 1.5px |
| `WHITE_ZONES` 超出四个定位块中心构成的四边形 | 外插到面板黑边上，用比真实白低 30 倍的值去拟合光照场，把 39% 的光照不均报成 51%/76% |
| `profile_from_samples` 把归一化结果裁进 `[0,1]` | 黄色红通道 1.55 被裁成 1.0，ΔE76 24 |
| 「任何墨色都不能在任一通道比白亮」这条不变量 | 物理上错的（饱和黄合法地超白），把唯一一张可用的 RAW 判成相机处理 |

另外两处指标口径也修了：光照均匀性改为判断**校正后**四条白边是否一致
（本例 39% → 0.6%），而不是判断原始梯度大小；`residual` 改为相对值，
否则把画面曝亮一档就会因为绝对残差变大而误报。
